ÉTAPE 2 - CE QUE LA FUSION VA REMONTER SUR VOS FICHES MAÎTRES
======================================================================
Lors d'une fusion HubSpot, la fiche conservée GARDE ses valeurs, mais ses champs VIDES sont remplis depuis le doublon. 61 valeur(s) remonteront ainsi après vos fusions - elles ne sont PAS dans le CSV livré.

La fusion native ne fait pas cette distinction - c'est donc à vous de vérifier.
Détail ligne par ligne : onglet << Fusion_valeurs_remontees >> du rapport Excel, À CONSULTER AVANT de lancer vos fusions.

======================================================================
POURQUOI CES CSV S'APPELLENT << ne_pas_ouvrir >>
======================================================================
1 valeur(s) de votre base commencent par = + - ou @. Ce sont le plus souvent les
téléphones que ce nettoyage vient de normaliser au format international, du type
+33612345678.

HubSpot les importe comme du TEXTE, sans aucun problème. Elles sont donc livrées
TELLES QUELLES dans les CSV : les préfixer d'une apostrophe pour protéger Excel
écrirait << '+33612345678 >> dans vos fiches, et corromprait la donnée pour se
protéger d'un risque qui n'existe pas à l'import.

EXCEL, lui, lit ces caractères comme le début d'un CALCUL. Il afficherait
33612345678 au lieu de +33612345678 : le préfixe international disparait. Si vous
enregistrez par-dessus, le format que ce nettoyage vient de produire est détruit,
et c'est cette version dégradée que vous importeriez. Voilà la seule et unique
raison du << ne_pas_ouvrir >> dans le nom de ces fichiers.

  - Pour IMPORTER : chargez le fichier directement dans HubSpot, sans l'ouvrir.
  - Pour LIRE ces valeurs : ouvrez le rapport Excel. Elles y sont forcées en texte,
    affichées a l'identique et jamais evaluees.
  - S'il faut absolument ouvrir un CSV : Données > Obtenir des données > A partir
    d'un fichier texte/CSV, en déclarant toutes les colonnes en << Texte >>.

A VÉRIFIER DANS HUBSPOT AVANT DE LANCER CET IMPORT (5 MINUTES)
======================================================================
Un import en masse peut redéclencher vos workflows et envoyer des emails automatiques
ou creer des tâches en double. Cette vérification se fait dans votre portail - nous ne
pouvons pas la faire depuis votre fichier d'export.

1. Paramètres > Propriétés. Recherchez chaque propriété que ce fichier modifie :
   Email, Phone number, Lifecycle stage, Lead status (+ vos propriétés personnalisées).
2. Pour chaque propriété, ouvrez sa fiche puis l'onglet << Used in >> (Utilisé dans) et
   basculez sur Workflows : la liste montre tous les workflows qui la référencent.
3. Pour chaque workflow ACTIF de cette liste, ouvrez le déclencheur d'inscription :
   se déclenche-t-il sur cette propriété (<< is known >>, << has changed >>) ? La
   re-inscription est-elle activée ?
4. Si oui a l'un des deux : DÉSACTIVEZ le workflow (bouton << Turn off >>) avant
   l'import, puis réactivez-le une fois l'import vérifié. Attention : les << pause
   dates >> ne suffisent pas, elles n'empêchent pas les nouvelles inscriptions.
5. À l'import, ne cochez la case de consentement que si ces contacts s'attendent
   réellement a recevoir de vos nouvelles. Jamais pour un fichier acheté ou scrape.

======================================================================
HubSpot ne propose AUCUNE annulation en masse d'un import terminé. Votre sauvegarde
est le seul filet de sécurité réel.

1. AVANT l'import : exportez l'état actuel de vos contacts (toutes propriétés) et
   conservez ce fichier horodaté de côté.
2. Importez d'abord un ÉCHANTILLON de 20 a 50 lignes. Vérifiez le résultat dans

3. En cas d'erreur après import complet : HubSpot conserve l'historique des imports
   (Data Management > Data Integration) et permet de télécharger les lignes en erreur,
   mais ne permet PAS de défaire un import réussi. La correction se fait par un
   nouvel import cible (avec Record ID) ou par édition en masse.
